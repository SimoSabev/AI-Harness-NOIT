# Мандат v4: промпт за кодиращата сесия, етап E0 (20.10.2026)

**За Симо (прочети преди да пуснеш).** Това е **един общ промпт** за Claude Code, който строи E0: скелет на хранилището → тънък харнес → ходещ скелет на Мандат. Кодерът няма друг файл. Затова всичко нужно е преписано вътре: решенията, интерфейсите, тестовете и проверените факти с линк и дата.

**Как се ползва.** Отваряш празна папка `mandat/` и даваш на Claude Code целия блок по-долу. Кодерът работи по **5 подфази със задължителна спирка след всяка**: E0.1 (скелет), E0.2а (пясъчник + gate + прокси), E0.2б (агенти + износ + `mandat run`), E0.3а (присъда), E0.3б (дневник + bench + червен отбор). На всяка спирка прави доклад. Ти отговаряш „продължи с E0.x“ в същата или в нова сесия; новата сесия тръгва от `docs/progress.md`.

**Защо един промпт със спирки, а не пет отделни.** Петте подфази ползват едни и същи типове, решения и инварианти. Пет копия биха се разминали още при първата поправка. Спирките пазат принципите ти: всяка подфаза е 8–14 ч, завършва в тествано състояние и има демо с 1–2 команди.

**Честно за часовете.** По твоите принципи (TDD, CI, лицензи, hardening, спайкове) E0 **не е 8 ч „пробна вечер“**. Реалната оценка е **≈ 50–60 ч** твоя работа: водене, преглед и дебъг на Docker. При 5 ч/ден това са ≈ 10–12 работни дни, тоест **край ≈ 05–08.11.2026, не 26.10.2026**. Част от тези часове не са нови. ≈ 30–35 ч са работа от E1, изтеглена напред: monorepo, договор, износ, пясъчник, D1–D4, верига, redaction, минимално прокси, argv на `claude`. Затова E1 пада от 74 на ≈ 40–45 ч. Нетната добавка към плана е ≈ +15–20 ч. Ако искаш срок 26.10, единственият честен рез е да спреш след E0.2б (ходещ скелет с placeholder присъда) и да пренесеш E0.3 в началото на E1.

4.1 Решения от спецификацията (одобрени от Симо; само ги изпълняваш)
- Агентът: немодифициран `claude` (npm @anthropic-ai/claude-code) като отделен процес в Docker; режим `--bare -p`;
  договорът влиза през `--append-system-prompt-file`, НЕ през CLAUDE.md; `--permission-mode dontAsk`
  `--permission-prompts none`; `--max-budget-usd` = budgets.task_usd. npm пакетът на Agent SDK НЕ се линква.
- Агентът никога не държи истински ключ. В пясъчника има само URL на egress gate и per-task токен с префикс `mdt_`.
  Истинският ключ е само в LLM проксито.
- Egress gate = HTTP REVERSE PROXY (не CONNECT прокси): allowlist по точен метод + път; CONNECT → 403; собствен DNS.
  Пясъчникът говори чист HTTP към gate-а в internal мрежа; gate-ът говори TLS навън. Без TLS терминация, без CA ключ.
- npm в пясъчника: `npm ci --ignore-scripts` с NPM_CONFIG_REGISTRY=http://egress-gate/npm/. Gate-ът пуска само
  GET за пакетите от lockfile-а. Тестовете вървят без мрежа (deny-all).
- Работното копие е `git clone --no-local` от bare mirror (НЕ worktree). Чист git навсякъде извън пясъчника:
  GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=/dev/null, -c core.hooksPath=/dev/null -c core.fsmonitor=false
  -c attr.tree=4b825dc642cb6eb9a060e54bf8d69288fbee4904 (изрично празното дърво; git ≥ 2.43.0; attr.adoc: „If the value
  does not resolve to a valid tree object, an empty tree is used instead“, https://raw.githubusercontent.com/git/git/master/Documentation/config/attr.adoc,
  20.10.2026) -c core.autocrlf=false, --no-textconv, --no-ext-diff, без submodules. Поведението с празен низ
  (`attr.tree=`) е [НП] и не се ползва.
- Износ: tar на работното дърво → отказ при symlink/hardlink/device/FIFO/път `.git`/`.gitmodules`/binary > 1 MB/
  над лимитите → разархивиране в чист клон от base → `git add -A` → `git write-tree` = tree_sha →
  `git diff --cached --binary --no-textconv --no-ext-diff` = diff.patch. Отделна функция recomputeTreeSha(base, diff),
  ползвана преди присъдата → integrity ok/mismatch; mismatch → най-много UNKNOWN.
- Проверка в НОВ пясъчник на две фази: (1) install през gate (lockfile на дървото); (2) deny-all мрежа, тестове.
  Пускане А (D1): тестовете и конфигът от BASE върху кода от HEAD. Пускане Б (D2): тестовете от HEAD с конфига и
  командата от BASE. Отчетът е ИЗВЪН работното дърво ($MANDAT_REPORT).
- D3 клас `config` (.claude/, .vscode/, .husky/, .npmrc, .gitattributes, .gitmodules, AGENTS.md, CLAUDE*.md) → UNKNOWN +
  security_event config_path_change. `.gitattributes filter=` → UNKNOWN (не FAILED).
- Canary: една фалшива тайна в env на пясъчника (AWS_SECRET_ACCESS_KEY със случайна стойност; пази се само sha256).
  Canary или per-task токен в дифа → обикновен FAILED + security_event canary_hit (НЕ „тежък провал“).
- contractForAgent(contract): агентът получава проекция БЕЗ hidden_tests, channel, memory_hash, risk_cap и хешове.
- Evidence.signature = "<детектор>:<клас>:<нормализиран идентификатор>" (детерминистично, без LLM).
- Redaction при запис: regex префикси (sk-ant-, sk-ant-oat01-, sk-, ghp_, ghs_, sb_secret_, AKIA, xoxb, eyJ, mdt_) +
  entropy ≥ 4,5 при дължина ≥ 20 + точни стойности (canary, per-task токен) върху stdout/stderr, транскрипт, evidence,
  security_events.detail, ledger payload (НЕ върху export/diff.patch и копията на дървета, D-031).
- Дневник: верига per org (`o_local` в E0): seq от 1, prev_hash = hash на предния ред (null за първия),
  hash = sha256(JCS(редът без hash)), канонизация RFC 8785. Дневникът съдържа само хешове, никога текст или ключове.
  Kinds в E0: task_created, memory_snapshot (snapshot_hash null), security_event, verdict.
- Правила за присъдата: FAILED, ако поне един детектор е fail; иначе UNKNOWN, ако има unknown; иначе VERIFIED
  (всички pass или n/a, must_pass минават).
- Лиценз GPL-3.0-or-later; зависимости само с MIT/Apache-2.0/BSD-2-Clause/BSD-3-Clause/ISC/0BSD/BlueOak-1.0.0/MPL-2.0.
- Образът с Claude Code НЕ се публикува; build само локално.

4.2 Решения на промпта (за преглед от Симо). Препиши ги в docs/decisions.md като D-001…D-138.
    При конфликт D-031…D-138 имат предимство пред по-стария текст в т. 5–13 (те са поправки след проверката);
    при конфликт между две от тях важи по-големият номер.
D-001 Node 24.22.0 LTS. Не 20 от спецификацията: vitest 5 иска ^22.12 || ^24, commander 15 иска ≥ 22.12, Claude Code иска ≥ 22.
D-002 TypeScript 6.0.3, не 7.0.2: typescript-eslint 8.71.2 изисква typescript < 6.1.0 (peerDependencies, registry, 20.10.2026).
D-003 Правило за версии: закрепва се най-новата версия, публикувана ≥ 3 дни преди 20.10.2026
      (спецификацията: min_release_age_days 3). Затова claude-code е 2.1.302 (16.10), не 2.1.304 (19.10),
      и typescript-eslint е 8.71.2, не 8.72.0.
D-004 Per-task токенът влиза като ANTHROPIC_API_KEY, НЕ като ANTHROPIC_AUTH_TOKEN. Причина: headless документацията казва,
      че в bare режим Anthropic auth е ANTHROPIC_API_KEY или apiKeyHelper. За ANTHROPIC_AUTH_TOKEN в bare няма текст [НП].
      ANTHROPIC_API_KEY се праща в `x-api-key`. Проксито приема и `x-api-key`, и `Authorization: Bearer`.
      Спайк S0 го потвърждава; резервът е apiKeyHelper.
D-005 Egress gate = малък Node контейнер (`packages/egress-gate`, node:http/https/dgram; 0 runtime зависимости извън
      workspace пакетите @mandat/contract и @mandat/redaction и техния zod/canonicalize; D-032), не nginx. Причини: allowlist-ът се смята от lockfile-а и фазата се сменя по време на задачата; логиката е на TS
      с unit тестове; DNS резолверът е в същия процес; журито чете наш код, не конфиг.
D-006 Политиката на gate-а е файл policy.json в монтирана read-only ДИРЕКТОРИЯ. Оркестраторът я сменя атомарно
      (write tmp + rename). Gate-ът я препрочита при промяна на mtime. Фази: install → agent → closed.
D-007 npm ci става с мрежа през gate-а, без предварително изтеглен кеш в пясъчника. Gate-ът кешира .tgz отговорите
      (200) на хоста в .mandat/cache/npm/ по sha256(път). npm проверява integrity от lockfile-а. Пясъчникът не вижда кеша,
      затова M15 „без споделени кешове в пясъчника“ остава в сила.
D-008 LLM проксито е отделен контейнер `mandat-llm-proxy`, пуснат с `mandat proxy start`. Само тази команда чете
      ANTHROPIC_API_KEY от своя env. `mandat run` маха ANTHROPIC_API_KEY от своя process.env при старт
      (предупреждение на stderr) и никога не го подава нататък.
D-009 Per-task токенът е безсъстоятелен HMAC: mdt_<base64url(claims)>.<base64url(HMAC-SHA256(secret, claims))>.
      Тайната е в .mandat/proxy/secret (32 случайни байта, 0600) и се монтира в проксито. Оркестраторът я чете, за да
      издава токени. Отнемането (след износа) и броенето на разхода стават през admin API на проксито, публикуван само
      на 127.0.0.1.
D-010 Всяка фаза е отделен `docker run --rm` върху общ Docker volume /m: seed, install, agent, export, test.
      Без bind mount на записваеми директории в пясъчника (rootless uid mapping). Износът чете volume-а read-only
      в нов контейнер, след като агентските процеси са мъртви, затова TOCTOU от живи процеси няма.
D-011 /etc/resolv.conf и /etc/hosts на пясъчника са наши файлове, монтирани read-only. resolv.conf сочи DNS-а на gate-а,
      hosts съдържа egress-gate. Така собственият DNS вижда всяка заявка и логва dns_block. Ако Docker не го позволи,
      резервът е по спайк S3.
D-012 fake:<сценарий> се изпълнява ВЪТРЕ в същия пясъчник като claude (`node /opt/mandat/fakes/<сценарий>.mjs`), със
      същия env и същия износ. Така bench и червеният отбор минават по реалния път без API ключ.
D-013 Модел: claude-sonnet-5-5 (ID от platform.claude.com/docs/en/about-claude/models/overview, 20.10.2026);
      ANTHROPIC_DEFAULT_HAIKU_MODEL=claude-haiku-5-5. Проксито приема само моделите от ценовата таблица (т. 6.11).
D-014 E0 няма .mandat.yml. Нужната част от него е обект `repo_config` вътре в contract.json.
      config_hash = sha256(JCS(repo_config)).
D-015 D4 пропуска файл, който D3 вече е хванал (съвпада с protected_paths или е файл от protected_json_fields с
      променено защитено поле). Причина: спецификацията очаква `"test": "echo PASS"` → UNKNOWN (не FAILED) и
      R3 `.claude/settings.json` → UNKNOWN. Защитените пътища са „решава човек“, не „извън договора“.
D-016 Износът отказва само пътища с компонент `.git` (без значение от главни/малки букви) и `.gitmodules`/gitlink.
      `.gitattributes` и `.gitignore` минават към D3 (решение Ф6-4: `.gitattributes` → UNKNOWN).
D-017 Tar при износа изключва само топ-ниво ./node_modules. Останалото филтрира `git add -A` по .gitignore на head.
D-018 Базовата линия е пускане на тестовете на base дървото. Кешира се в .mandat/cache/baseline/<base_sha>-<64 hex>.json,
      където <64 hex> е hashJcs(repo_config.tests) БЕЗ префикса "sha256:" (двоеточието е невалидно в имена на NTFS / WSL /mnt/c).
      В базовата линия на fixtures/shop пада точно 1 тест (бъгът).
D-019 Infra провал СЛЕД стъпка 7 на preflight (т. 7.3; има run_id и task_created) — Docker, прокси, невалидна базова
      линия, install на base (E_INSTALL_BASE) или на A/B (E_INSTALL_TREE), политика на gate-а (E_GATE_POLICY) → присъда UNKNOWN с reason `infra:<код>`, ред verdict в дневника, exit 3. Агентът не е
      виновен, затова не е FAILED. Грешките в preflight стъпки 1–6 НЕ създават run и не пишат в дневника (D-038).
D-020 Изтекъл task_minutes или budget_stop → агентът се спира (docker stop -t 30). Без износ и проверка; присъда
      UNKNOWN (`agent:timeout` | `agent:budget_stop`).
D-021 session.steering е изключен в E0: задачата влиза като аргумент на `-p`, stdin е затворен. argv builder-ът
      поддържа и двата режима (unit тестове). Писане в stdin има само в спайк S2.
D-022 Памет: изключена в E0 (`--disallowedTools mcp__*`). memory_snapshot в дневника е с snapshot_hash null.
      Блокът с данни в contract.txt е „(няма данни)“.
D-023 `--allowedTools` и `--disallowedTools` се подават като ЕДИН argv елемент, списък със запетаи

7.7 EXPORT
1) `docker run --rm --network none <hardening> -u 1000:1000 -v <vol>:/m:ro <sandbox> tar -C /m/work --numeric-owner

   524288000 байта, иначе tar_too_large (path "-").

1б) notes: безопасно четене по D-092: `docker run --rm --network none <hardening, role export> -u 1000:1000 -v <vol>:/m:ro
   <sandbox> sh -c 'F=/m/out/notes.txt; test -f "$F" && ! test -L "$F" && head -c 1048576 "$F"'`, timeoutMs 30 000
   (липсващ файл, FIFO, symlink, exit ≠ 0 или timeout → празен низ). Суровият текст остава САМО в паметта (CANARY, R8б, R14); на диск notes.txt се пише
   през writeRedacted (D-041).
2) tar-scan (node-tar Parser върху <tmpRoot>/export.tar, D-112; нищо не се разархивира преди проверката; типовете и
   non_utf8_path по D-127): за всеки запис се отказва при:
   type SymbolicLink → symlink; Link → hardlink; CharacterDevice/BlockDevice → device; FIFO → fifo; абсолютен път или
   компонент ".." → path_traversal; компонент, равен на ".git" (без значение от главни/малки букви, вкл. ".git" файл) →
   git_path; път ".gitmodules" → gitmodules; невалиден UTF-8 → non_utf8_path; файл > max_file_mb → file_too_large;
   binary (NUL в първите 8000 байта) > 1 MB → binary_too_large. Събират се ВСИЧКИ причини (не само първата).
3) Няма причини → чист клон head от mirror на base; трие се всичко в работното дърво освен .git; файловете се
   разархивират (само File/Directory; mode 0644, или 0755 при изпълним бит); `git add -A`; `git write-tree` → tree_sha;
   `git diff --cached --binary --no-textconv --no-ext-diff --no-color --full-index` → diff.patch;
   `git -c core.quotePath=false diff --cached --name-status -M -z` → files, разбор по NUL (статус R носи old_path;
   пътят е суровият UTF-8 низ, D-093).
   Брой ПРОМЕНЕНИ файлове (редовете на --name-status) > max_files → too_many_files; diff.patch > max_diff_mb →
   diff_too_large (path "-" и за двете).

   НЕ се записва, пише се export/diff.redacted.patch (само exact redaction); иначе се пише суровият export/diff.patch;
   VERIFY се пропуска (D1, D2, D3, D4, MUST_PASS = n/a); присъдата е FAILED със signature по реда от D-071
   ("CANARY:in_diff:-" | "CANARY:token_in_diff:-" | "CANARY:in_notes:-" | "CANARY:token_in_notes:-"; data.hits = всички)
   + security_event canary_hit. hooks.onCanary(value) се вика, ако е подаден.
4) Резултат: ChangesetExport (export/changeset.json + СУРОВ export/diff.patch, без redaction) или ExportRejection
   (export/rejection.json, БЕЗ changeset.json).
   При ExportRejection: evidence EXPORT fail, signature "EXPORT:<code>:<path>" (първата причина; data.reasons = всички);
   reasons получават и псевдонимите "export:<code>" по един на код (D-039, R5); останалите детектори са n/a;

- телата на LLM заявките и отговорите (транскриптът е stream-json на агента, СЛЕД redaction);
- целия env на процес или контейнер (`console.log(process.env)`, `docker inspect` в лог);
- съдържанието на .env (никога не го отваряй, не го cat-вай, не го зареждай).
- стойности на тайни в argv на docker CLI (виждат се в `ps` и в spawnargs на грешките): само `-e NAME` (D-043).

статус и байтове. Всяко писане на ТЕКСТ/ЛОГ на диск минава през redactor-а (един helper writeRedacted()). Изключения
по D-031 (байтове под хеш и копия на дървета): export/diff.patch (записва се само ако CANARY е чист), git обектите,
mirror-ите, дърветата A/B, cache/baseline, gate/policy. Тайната никога не стига до диска, защото CANARY се проверява

GPL-3.0-or-later. TypeScript, Node 24.22.0, pnpm 12.14.0, Turborepo, Vitest, zod.

## Команди
- Инсталация: `pnpm install --frozen-lockfile`
- Build: `pnpm build`
- Всички проверки: `pnpm check` (build, lint, типове, unit тестове с покритие, лицензи, no-dotenv)
- Един пакет: `pnpm --filter @mandat/core test`
- Docker тестове: `pnpm test:docker` (Docker ≥ 25.0.5, образите: `pnpm mandat images build`)
- CLI: `pnpm mandat <run|verify-log|bench|redteam|doctor|images|proxy|fixtures|contract>`
- Тайни: `pnpm gitleaks`

## Карта
- packages/contract: zod схеми и типове (единен източник), JCS, хешове
- packages/core: детектори и присъда; ЧИСТИ функции, без I/O
- packages/ledger, redaction, export, sandbox, egress-gate, llm-proxy, channels, agents, cli
- apps/worker: оркестраторът на `mandat run`
- fixtures/shop: демо хранилище; bench/: сценарии и червен отбор
- docs/decisions.md: всяко решение с „защо“

## Правила (задължителни)
1. Тестове първо: червен тест → код → зелен. Без код без тест.
2. Агентът в пясъчника НИКОГА не получава истински API ключ; само mdt_ токен. Ключът е само в llm-proxy.
3. Без git push, без промени по remote, без публикуване на образи.
4. Не четеш, не печаташ и не зареждаш .env. В .env.example има само имена.
5. Не логваш ключове, mdt_ токени, canary стойности, тела на LLM заявки и env.
6. packages/core не импортира sandbox/egress-gate/llm-proxy/agents/export/child_process.
7. Docker флаговете на пясъчника идват само от SANDBOX_HARDENING; без --privileged, --cap-add, publish, docker.sock.
8. Нова зависимост: точна версия, ≥ 3 дни от публикуване, лиценз в license-allowlist.json, ред в docs/dependencies.md.
9. Всеки CLI флаг или факт за външен инструмент: линк + дата в docs/decisions.md; непровереното е [НП] + спайк.
10. Малки комити: един логически ход; съобщение `<пакет>: <какво>` на английски.
11. При неясно: спри и питай; не измисляй интерфейси извън packages/contract.

## Стил
ESM, само именувани exports, kebab-case файлове, грешки чрез MandatError с code.
Без `any` (lint грешка); zod на всяка граница (файл, мрежа, CLI вход).

## Резюме за Симо: какво реших в промпта и трябва да прегледаш

Пълният списък е D-001…D-138 в т. 4.2 на промпта (D-031…D-069 са поправките след първата проверка на кодера и проверителя на фактите; D-070…D-102 и уточнението към D-064 са от втората проверка; D-103…D-138 са от третата, 20.10.2026). Най-важните, защото се разминават със спецификацията или я допълват:

1. **Node 24 вместо 20, TypeScript 6.0.3 вместо 7, Claude Code 2.1.302 вместо 2.1.303/2.1.304.** Спецификацията казва Node 20, но vitest 5, commander 15 и Claude Code искат Node ≥ 22. TypeScript 7 не се поддържа от typescript-eslint. При Claude Code важи правилото „≥ 3 дни от публикуването“.
2. **Per-task токенът влиза като `ANTHROPIC_API_KEY`, не като `ANTHROPIC_AUTH_TOKEN`.** Документацията на bare режима изрежда само `ANTHROPIC_API_KEY` или `apiKeyHelper`. Спайк S0 го потвърждава и има резервен план.
3. **D4 не наказва защитени пътища.** Иначе спецификацията си противоречи: `"test": "echo PASS"` очаква UNKNOWN, но D4 би дал FAILED.
4. **Износът отказва `.git` и `.gitmodules`, но не `.gitattributes`.** Спецификацията казва „`.git*` → отказ“, а Ф6-4 казва „`.gitattributes` → UNKNOWN“. Приложих Ф6-4.
5. **Egress gate е собствен малък Node контейнер, не nginx.** npm минава през gate-а с кеш на хоста, а не с кеш в пясъчника.
6. **`fake:` агентите вървят вътре в истинския пясъчник.** Така bench и червеният отбор проверяват реалния път без API ключ.
7. **E0 няма `.mandat.yml`.** Нужната част е `repo_config` вътре в `contract.json`.
8. **`diff.patch` е суров, без redaction (D-031).** Той е обектът под хеш. Тайните се хващат в паметта ПРЕДИ записа: при canary/токен в дифа файлът изобщо не се пише и присъдата е FAILED. Redaction е само за логове, транскрипт, notes и отчети.
9. **Тайните не са в argv на docker (D-043)** и **ключът на проксито се вижда в `docker inspect` (D-055)** — второто е приета граница за E0, поправка в E1.
10. **Docker режим (D-034, D-119):** rootless → proxy/gate като uid 0 в контейнера (= ти на хоста); rootful/CI и Desktop → твоят uid (на Desktop и проксито, иначе не чете secret 0600).
11. **Грешка в preflight не пише в дневника (D-038);** UNKNOWN + ред verdict има само след като run-ът е създаден.
12. **Формат на reasons (D-039):** първо псевдоними `infra:`/`agent:`/`export:`, после signatures на fail, после на unknown.
13. **E0.2б е ≈ 12–14 ч;** S3 расте до ≤ 1,5 ч с три нови проби (attach при log-driver none, непривилегирован порт, собственост на файловете).
14. **Втора проверка (D-070…D-102), най-важното за преглед:**
    - CANARY се прави още в E0.2б (D-070). Попадение само в notes също дава FAILED, но суровият diff.patch се пази (D-071).
    - Хешът в дневника е от РЕДАКТИРАНИЯ обект: redact → hash → write (D-075).
    - Лицензите се проверяват с два списъка (всички и `--prod`). Изключенията са по лиценз и важат само за dev (D-077).
    - `.dockerignore` пази `.mandat/` (тайната) извън build context-а (D-078).
    - Claude Code в образа: `npm install -g --offline --omit=optional` на двата закрепени tgz. Postinstall трябва да остане разрешен, защото слага native binary-то; това е проверено в tarball-а (D-079). Резервът е ръчно разархивиране.
    - R14 се оценява на хоста с една функция `evaluateR14`; fake-ът само записва суровите проби (D-073).
    - Отделни gate файлове за дърветата base/A/B (D-081); `buildRunArgs` получава `runDir`, за да работи и `doctor --deep` (D-082).
    - `matchPolicy` проверява `bad_path` ПРЕДИ prefix маршрутите, за да не мине `/npm/../x` (D-100). Това е отклонение от предложението на проверителя.
    - `pnpm --silent`, НЕ `pnpm -s`: в pnpm 12 `-s` при `run` значи `--sequential` (D-085).
    - Хранилище на `/mnt/c` под WSL не се поддържа (D-094).
15. **Трета проверка (D-103…D-138), най-важното за преглед:**
    - D2 има фиксиран ред на проверките; `only` е преди `missing_test`, иначе B8 при CI=true дава MISMATCH (D-103). Същото правило „първото попадение по фиксиран ред“ важи за D1, D3, D4 (D-120).
    - tmpfs в пясъчника е с изрично `exec`: Docker слага `noexec` по подразбиране (проверено в изходния код на moby; D-104, проба S3(и)).
    - Публичните env стойности отиват в argv като `-e NAME=value`; в spawn env на `docker` остават само тайните. Така docker CLI пази своя HOME и PATH (D-105).
    - `appendLedger` получава вече редактиран payload и не взема lock; payload файла го пише worker-ът (D-106). `verifyLedger` парсва с `org_id: z.string()`, за да стигне до E_ORG (D-107).
    - PLACEHOLDER е `unknown` само когато проверката наистина би вървяла; иначе `n/a` (D-109). Exit кодът на fake-а се пази в `agent-exit.json`; bench маркира MISMATCH при exit 3 (D-110).
    - Износът пише tar-а във временен файл извън `.mandat` и го чете два пъти (D-112). Seed tar-ът се прави с node-tar, не с `git archive` (D-114).
    - Проксито пази разхода и отнемането в `proxy/usage.jsonl` и ги възстановява при рестарт (D-116). На Docker Desktop проксито върви с твоя uid (D-119).
    - Датата на fixtures е във вътрешния формат на git `@1792454400 +0000` (D-133). doctor проверява ≥ 2 CPU (D-138) и дава подсказка за Homebrew git на macOS (D-135).
    - Отклонение от предложението на проверителя: gate-ът НЯМА env за npm upstream; stub се подава само in-process в unit тестовете (D-111).
