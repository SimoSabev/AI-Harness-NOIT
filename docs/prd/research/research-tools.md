### 1.2 Takeaways for the PRD

1. Only four of the surveyed APIs return **quote-level evidence tied to a specific claim**: Anthropic web search (`cited_text` ≤150 chars per citation), Anthropic web fetch with `citations.enabled` (char offsets into the fetched document), Gemini grounding (`groundingSupports` segment→chunk with confidence), and Parallel Task API (per-field basis). OpenAI gives char spans in *its own* answer but no source quote. Perplexity/Tavily/Exa return source lists and snippets but the claim↔source link is only an inline `[n]` marker (and Perplexity has a documented mis-mapping bug).
2. Cheapest raw retrieval: Brave/Parallel/Perplexity Search ≈ $5/1k; Exa $4–7/1k; Anthropic web search $10/1k; Gemini 3 $14/1k queries; OpenAI ≈$10/1k. Full-page fetch is cheapest via Anthropic web fetch (tokens only) or Jina (≈$0.05/M tokens); Firecrawl/Tavily extract charge per page.
3. For code/library facts, prefer first-party sources with stable URLs: Context7 (versioned docs), DeepWiki (free, public repos), GitHub code search (10/min), Sourcegraph (enterprise). For papers: Semantic Scholar (1 RPS), Crossref polite pool (3 r/s), arXiv (≈1 req/3 s).

### 2.2 How vendors mark citations (for parsing)

- Anthropic: `citations[]` on text blocks — `web_search_result_location{url,title,cited_text,encrypted_index}` (search) and `char_location{document_index,start_char_index,end_char_index,cited_text}` (fetch); also `search_result` content blocks for RAG with `source,title,citations` **[V]** (web-search/web-fetch docs above).
- OpenAI: `annotations[]{type:"url_citation",url,title,start_index,end_index}` on output text; Deep Research exposes `web_search_call` items [UNVERIFIED].
- Gemini: `groundingSupports[].segment{startIndex,endIndex,text}` → `groundingChunkIndices` → `groundingChunks[].web.uri` (redirect URI) with `confidenceScores` [UNVERIFIED].
- Perplexity: inline `[n]` + `search_results[]{title,url,date}` (and legacy `citations[]` list of URLs); known index mis-mapping bug [UNVERIFIED].
- Tavily research: numbered/MLA/APA/Chicago `citation_format`; `sources[]{url,title,citation}` **[V]** (vendor skill refs).

### 2.5 Recommended verification pipeline for the harness

1. Retrieval returns (url, title, snippet/quote, retrieved_at). Reject any citation without a URL that appeared in a tool result (mirror Anthropic's "URL must appear in prior context" rule — prevents the model inventing URLs).
2. Fetch the page (Anthropic web fetch with `citations.enabled`, or Jina/Firecrawl/Tavily extract), store text + SHA-256 + final URL + status.
3. For every claim, require a `cited_text` span that string-matches (after whitespace/Unicode normalization) inside the fetched text; if absent, run an NLI/LLM-judge "supported / partial / unsupported / contradicted" check and flag anything below "supported".
4. Archive the URL (SPN2) asynchronously; record the snapshot URL and CDX digest; fall back to local copy if archiving fails.
5. Emit a per-claim verdict in the output and a machine-readable evidence list (JSON) in the ledger; surface counts (supported / unsupported / unresolvable) to the user. Expect 5–20% of agent-generated citations to need repair based on the studies above.

### 4.5 What a harness should do to vet and sandbox MCP servers (synthesis of OWASP cheat sheet, Docker, Invariant, Anthropic docs)

1. **Allowlist by identity, not by name**: resolve each server to (registry name, exact version, package digest / OCI image digest, remote URL + TLS cert). Pin versions; reject `@latest`. Mirror Claude Code's `deniedMcpServers` / `managed-mcp.json` policy pattern and its rule that a checked-out repo cannot enable browser tools (AGENTS.md rule 8 already demands exact versions ≥3 days old).
2. **Hash tool definitions**: SHA-256 over canonical JSON of `{name, description, inputSchema}` at first approval; re-hash on every `tools/list` and on `notifications/tools/list_changed`; any change = block + re-approval (defeats rug pulls). Store hashes in the ledger.
3. **Scan descriptions** for instruction-like text (imperatives, "ignore", "read file", hidden Unicode, `<IMPORTANT>` blocks) with `mcp-scan` or an LLM classifier; show full descriptions to the approver, not truncated ones.
4. **Run every local server in a container** with no host FS beyond an explicit mount, read-only root, no Docker socket, dropped capabilities, memory/CPU limits, and egress limited to the server's declared hosts (Mandat's SANDBOX_HARDENING + egress-gate already model this; the LLM proxy keeps real keys out of the sandbox).
5. **Secrets**: inject per-server credentials at launch from a vault/Docker secrets; the model never sees them; prefer OAuth 2.1 + PKCE + resource indicators for remote servers; short-lived tokens.
6. **Isolate servers from each other**: separate processes/containers; present each server's tools with a provenance prefix; do not let one server's descriptions reach another server's call context (cross-server shadowing).
7. **Treat all tool results as untrusted data**: strip/flag instruction-like content before it re-enters the prompt; apply the web-fetch rule "only act on URLs that came from the user or a tool result".
8. **Gate consequential tools**: write/delete/send/pay/exec require human confirmation; map each tool to a risk class in config; log every call (args hash, result hash, duration) to the ledger.
9. **Rate-limit and budget** per server and per session (requests, tokens, dollars) — gateways like Portkey/agentgateway do this; a harness can do it in the proxy.
10. **Continuous checks**: re-scan on update, watch CVE feeds for pinned servers, and keep an SBOM per release.
