Date of research: 2026-10-22. All URLs below were read on that date unless noted.

## 0. Method, reach, and verification legend
- Tools used: WebSearch (snippets + search-engine summaries) and WebFetch. In this session WebFetch could only resolve `github.com` / `raw.githubusercontent.com`; every other host (vendor docs sites, arXiv, HF, Google blogs) failed DNS through the proxy, and the WebSearch budget ran out after ~55 queries. So:
  - **[VERIFIED]** = read directly from an official GitHub README / in-repo docs / CHANGELOG.
  - **[UNVERIFIED]** = only seen in search snippets or third-party pages (pricing figures especially; several sources conflicted). Treat any price here as "order of magnitude" until checked on the vendor page.
- Theme that matters for this PRD: the space churns fast. Within the last ~9 months: Terragon shut down (Feb 2026), Crystal was deprecated for Nimbalyst (Feb 2026), Vibe Kanban is "sunsetting" (bloop shutdown, ~Apr 2026), Roo Code was archived (15 May 2026), coder/AgentAPI is deprecated, Kimi CLI was replaced by Kimi Code CLI, coder/mux was renamed Xum, Daytona's OSS repo was archived (June 2026), and the Gemini CLI README says it "was replaced by Antigravity CLI on June 18th, 2026" for unpaid/Google One tiers. Anything built on one vendor's harness is a liability; an agent-agnostic harness is the durable layer.

Column definitions used throughout: **Onboarding** = does the product detect build/test/risk and propose rules; **Config** = instruction/rule files it reads; **Multi-agent** = can it drive other vendors' agents/models; **Parallel** = worktrees/sandboxes for N concurrent runs; **Sandbox** = OS/VM isolation; **Verify** = how results are checked (tests, review, independent judge); **Approvals** = human-in-the-loop model; **Delivery** = how work lands in git; **Visibility** = dashboard/live view; **Platforms**.

### A1. Gemini CLI (Google) — Apache-2.0 [VERIFIED for repo docs]
- What: open-source terminal agent. README now states it "was replaced by Antigravity CLI on June 18th, 2026" for unpaid-tier and Google One users and "has not been optimized for Gemini 4 Argon" (README, github.com/google-gemini/gemini-cli). Paid/API usage of the CLI continues; the exact Antigravity split is **[UNVERIFIED]** beyond that README line.
- Config: `GEMINI.md` context files (hierarchical), `settings.json` layered Project (`.gemini/settings.json`) > User (`~/.gemini/settings.json`) > System (`/etc/gemini-cli/settings.json`) > Extensions. Extensions bundle MCP servers, commands, context files, skills, hooks, themes (`gemini-extension.json`).
- Hooks (docs/hooks/index.md): events `SessionStart, SessionEnd, BeforeAgent, AfterAgent, BeforeModel, AfterModel, BeforeToolSelection, BeforeTool, AfterTool, PreCompress, Notification`. Command hooks only; JSON on stdout; exit 0 = parsed decision, exit 2 = hard block with stderr as reason, other = warn & continue; default timeout 60 s. Hooks can add context, block/rewrite tool input, filter the tool list, adjust model params. Security: project hooks are fingerprinted and re-prompted when their command changes after `git pull`. `/hooks panel|enable|disable`.
- Policy engine (docs/reference/policy-engine.md): TOML rules in `~/.gemini/policies/*.toml` (user), admin dirs (`/etc/gemini-cli/policies`, must pass ownership/permission checks), extension policies; **workspace tier is currently disabled (issue #18186)**. Rule fields: `toolName`, `subagent`, `mcpName`, `toolAnnotations` (e.g. `readOnlyHint=true`), `argsPattern`, `commandPrefix`/`commandRegex`, `decision = allow|deny|ask_user`, `priority 0-999`, `modes`, `denyMessage`. Tier base + priority/1000 decides winner; global deny hides the tool from the model; `ask_user` acts as deny in non-interactive mode. Modes: `default`, `autoEdit`, `plan`, `yolo`; "allow always" grants are scoped by the mode they were given in.
- Sandbox (docs/cli/sandbox.md): macOS Seatbelt (`sandbox-exec`, 6 profiles; default `permissive-open` = writes limited to project dir, network open) or Docker/Podman (`ghcr.io/google/gemini-cli`, cwd mounted at same path, custom `.gemini/sandbox.Dockerfile`), enable via `-s`, `GEMINI_SANDBOX=`, or settings. Docs state sandboxing "reduces risk but does not eliminate it".
- Subagents (docs/core/subagents.md): Markdown+frontmatter in `.gemini/agents/` or `~/.gemini/agents/`; fields `tools`, `mcpServers`, `model`, `max_turns` (30), `timeout_mins` (10); built-ins `codebase_investigator`, `cli_help`, `generalist`, `browser_agent`. Subagents cannot spawn subagents. Remote A2A agents via `kind: remote` + agent card. Experimental local routing uses a Gemma-3-1B classifier served by LiteRT-LM (not Ollama) only for model-choice decisions.
- Multi-provider: Gemini only (plus A2A remote agents). Parallel: no built-in worktree manager. Verification: none beyond hooks. Delivery: user's git. Visibility: terminal; headless mode with JSON/stream-JSON output. Platforms: CLI (npm/brew), IDE companion.
- Sources: github.com/google-gemini/gemini-cli (README, docs/hooks/index.md, docs/reference/policy-engine.md, docs/cli/sandbox.md, docs/core/subagents.md, docs/core/remote-agents.md, docs/core/local-model-routing.md). Hooks announcement (28 Jan 2026) and v0.31 policy additions: developers.googleblog.com/en/tailor-gemini-cli-to-your-workflow-with-hooks/ [UNVERIFIED snippet].

## 2. The 10 biggest gaps nobody fills well
1. **No independent, adversarial verifier in the delivery path.** Every agent's "verification" is its own test run or a same-vendor LLM review. goose's adversary mode is per-tool-call and fail-open; Amp's Oracle advises the same agent; CodeRabbit/Bugbot/Codex review never execute code. Nobody ships a judge that (a) uses a different context/model, (b) runs the tests itself in a clean sandbox, and (c) is read-only to the worker.
2. **Test tampering is measurable but unmitigated in products.** ImpossibleBench/METR/BAITBENCH show 30-57% cheating when tests or graders are writable, and that hiding/locking tests nearly eliminates it. No harness enforces "tests are immutable during the run, re-run from the base commit by the judge, diff of test files is a hard flag."
3. **Auto-onboarding stops at an instructions file.** `/init`, ClaudeForge, repowise, analyzeRepo generate CLAUDE.md/AGENTS.md. Nothing detects build/test/lint commands, risk surfaces (migrations, auth, payments, infra), secrets, and emits a *complete* harness (policy rules, hooks, checks, permissions, skills) with a quality score. Kiro's spec→property-test is the closest and is single-vendor.
4. **Policy portability.** Each agent has its own permission dialect (Gemini TOML policies, Claude settings/hooks, Codex execpolicy/sandbox modes, Vibe config.toml, OpenCode opencode.json, goose per-tool). No translation layer; a harness that compiles one policy into N dialects does not exist.
5. **Worktrees ≠ sandboxes, and most orchestrators stop at worktrees.** Conductor, Superset (says so explicitly), Vibe Kanban, Claude Squad, Xum isolate files, not processes/network/secrets. Sandbox SDKs (E2B, Vercel, Cloudflare) exist but aren't wired to these UIs; Daytona's OSS runtime was archived and Terragon died trying.
6. **Delivery is "open a PR"; nobody gates on *proven* quality.** No product combines: judge verdict + CI + mutation score/coverage delta + diff-risk classification + policy compliance before anything reaches the user's repo. Symphony's "proof of work" is self-reported by the agent.
7. **Cross-agent live visibility + audit.** Claude Code emits OTel `safety_event`s; Gemini has hook fingerprints; Ona advertises guardrail audit trails — but no vendor-neutral dashboard shows N agents' tool calls, blocked actions, cost, and judge verdicts in one place.
8. **Mutation testing and spec-grounded testing are absent from agent loops** except as community skills; practitioner evidence shows feeding surviving mutants back improves tests. No product does this automatically or uses mutation score as a merge gate.
9. **Local-model use is all-or-nothing.** Gateways (LiteLLM, CCR) route *requests*; nobody routes *roles* (cheap local classifier for policy decisions and triage, mid-tier for edits, frontier for judging) with explicit cost/quality budgets per project. Gemini's Gemma-router is the lone, narrow precedent.
10. **Vendor churn risk is unmanaged.** Six orchestration products died or pivoted in nine months; AgentAPI's screen-scraping approach is deprecated. There is no stable, agent-agnostic adapter layer (ACP is editor↔agent, not orchestrator↔agent) with conformance tests, so every harness re-implements per-agent drivers.

## 3. Ideas proven in practice that should be copied
- **Git worktree per task + per-workspace setup/run scripts** (Conductor, Superset `.superset/config.json`, Vibe Kanban, Claude Code `--worktree`, Symphony hooks): cheap, understood by users, and fixes port/dependency collisions (Vibe Kanban port daemon).
- **Lifecycle hooks with a hard-block exit code and context injection** (Gemini exit 2; Claude Code `onFailure: "block"`, `PreToolUse additionalContext`; Vibe pre-tool deny; Kimi hooks). Also Gemini's **fingerprinting of project hooks** after `git pull` and Codex's **`allow_managed_hooks_only`** for enterprise control.
- **Declarative, prioritized policy rules with modes** (Gemini TOML: tool/MCP/annotation/argsPattern/commandPrefix, allow/deny/ask_user, tiered priority, `ask_user`→deny in headless): the best-designed permission model seen; copy its shape, add project tier (Gemini's is disabled).
- **Markdown-with-frontmatter as the unit of configuration** (subagents, remote agents, WORKFLOW.md, skills, Copilot `.agent.md`): human-reviewable, version-controlled, hot-reloadable with last-known-good fallback (Symphony).
- **Tracker-as-control-plane** (Symphony): states drive scheduling, "Human Review" as terminal handoff, operator stops a run by moving a card, never let the orchestrator write the tracker.
- **Independent reviewer as a *different context*** (goose adversary mode, Amp Oracle, Kimi K2's internal scorer for best-of-N): keep, but make it fail-closed and give it test execution.
- **Read-only/hidden tests for the worker** (ImpossibleBench mitigation) and **best-of-N with a judge** (K2 +5.8 pts): directly applicable to a verify stage.
- **Spec → property-based tests** (Kiro), **mutation-score loop** (Stryker/mutmut incremental modes make it cheap enough for CI).
- **Auto-mode classifier trained from project + recent sessions** (Claude Code `/auto-mode-setup`) and **safety events to OTel** — the right telemetry shape for a dashboard.
- **Per-sandbox egress allowlist and credentials-stay-outside** (Cloudflare Sandbox SDK; Symphony's `$VAR` secrets rule; Codex cloud network-off during agent phase).
- **Diff-comment → agent feedback loop** (Superset, Vibe Kanban) and **draft PR + human-approved CI** (Copilot).
- **ACP for editor integration** and **Anthropic-Messages-compatible gateways** (vLLM, LiteLLM, CCR) so any agent can be pointed at any model, including local.
