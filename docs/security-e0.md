# Сигурност в E0

Статус: E0.1. Пясъчникът, gate-ът и проксито идват в E0.2а; тук са инвариантите, които важат от първия ден, и какво
вече е изпълнено. Документът се допълва във всяка подфаза.

## Пътят на ключа (план)
`ANTHROPIC_API_KEY` съществува само в env на командата `pnpm mandat proxy start` → контейнер `mandat-llm-proxy`.
`mandat run` маха променливата от своя env (D-008). Пясъчникът получава `ANTHROPIC_BASE_URL=http://egress-gate` и
`mdt_` токен (HMAC, D-009), подаден като `-e ANTHROPIC_API_KEY` само с името (D-043).

## Docker конфигурация (т. 8.2) и режими (D-034)
Описва се в E0.2а заедно с `SANDBOX_HARDENING`. Rootless: proxy/gate като uid 0 в контейнера (= потребителят на хоста);
rootful/CI и Docker Desktop: `$(id -u):$(id -g)`; пясъчникът винаги 1000:1000.

## Закрепване по integrity
- Claude Code 2.1.302 (главният пакет и native binary-то за linux-x64/arm64) по sha512 от т. 4.3 и D-056; без TOFU.
- Базовият образ по digest на OCI индекса (D-058, сверен в E0.1: D-146).
- gitleaks образът по digest на OCI индекса (D-145).

## Redaction (E0.1)
`@mandat/redaction`: exact стойности → 8 префиксни правила → entropy ≥ 4,5 по сегменти (D-059) с allowlist; идемпотентно.
Корпус: 50/50 фалшиви ключа се редактират, 0/22 лъжливо положителни. Разширение D-140 (за преглед). `writeRedacted` е
единственият helper за текст на диск; байтовете под хеш (diff.patch, git обекти) НЕ минават през него (D-031).

## Известни граници
- Код от head може да подправи собствения си отчет във VERIFY.
- Честността на фаза 1 е толкова, колкото е здрав пясъчникът; kernel-ът е споделен.
- Ключът в env на проксито се вижда в `docker inspect` и е в конфигурацията на Docker на диска (D-055). E1: ключ в tmpfs
  файл с `MANDAT_PROXY_KEY_FILE`.
- Облачната сесия, в която е направен E0.1, е rootful Docker с cgroup v1 (D-148); спайкът S3 трябва да се пусне на
  целевата машина.
