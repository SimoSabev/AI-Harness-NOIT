# S3 — Docker механика (E0.2а)

Машина: облачният контейнер на сесията — Docker Engine 29.9.1, **rootful**, **cgroup v1**, 4 CPU, ядро без IPv6.
Целевата машина на Симо (rootless, cgroup v2) трябва да повтори пробите: `pnpm test:docker --project sandbox --project egress-gate`.

| Проба | Команда / тест | Наблюдение | Критерий |
| --- | --- | --- | --- |
| (а) resolv.conf/hosts ro в internal мрежа | docker тест „resolv/hosts mounts“ | `nameserver <gate ip>`; `getent hosts egress-gate` → gate ip; запис в /etc/resolv.conf → Permission denied | да |
| (б) DNS на gate-а вижда заявките | „gate DNS“ | evil.example → ENOTFOUND (NXDOMAIN), events.jsonl ∋ dns_block evil.example; AAAA egress-gate → ENODATA без dns_block | да → DNS_MODE "gate" |
| (в) --tmpfs …uid=1000 | „sandbox hardening“ | /home/agent е 1000 0700 (rootful; rootless не е пробвано тук) | да (rootful) |
| (г) --cpus/--memory/--pids-limit | ръчно + „sandbox hardening“ | pids.max = 512; memory.limit = 2147483648 (cgroup v1) | да |
| (д) volume наследява /m | „S3(д)“ | /m 1000, /m/in 0, /m/work 1000, /m/out 1000 | да → D-096 не се активира |
| (е) --log-driver=none + -i | „S3(е)“ | `echo hi` → "hi" | да |
| (ж) непривилегирован порт | `docker run --rm --user 1000 <gate> cat /proc/sys/net/ipv4/ip_unprivileged_port_start` | 0 | да → gate без --cap-add |
| (з) собственост на файловете на gate/proxy | ръчно | events.jsonl и usage.jsonl са на потребителя на хоста (тук uid 0, защото сесията е root) | да (rootful); desktop/rootless: на Симо |
| (и) tmpfs с exec | „sandbox hardening“ | скрипт в /tmp и в /home/agent печата "ok" | да |
| допълнително | всеки контейнер | `--sysctl net.ipv6.conf.all.disable_ipv6=1` → runc отказва: ядрото няма IPv6 | → D-152 |

Решение: DNS_MODE = "gate"; gate без cap-add; D-096 не се активира; D-152 за ядра без IPv6.
